# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

- **Model** - слой данных, отвечает за хранение и изменение данных.
- **View** - слой представления, отвечает за отображение данных на странице.
- **Presenter** - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

**Конструктор:**
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

**Поля класса:**
- `container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

**Методы класса:**
- `render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`
- `setText(element: HTMLElement, value: string): void` - утилитарный метод для установки текстового содержимого элемента.

#### Класс Api

Содержит в себе базовую логику отправки запросов.

**Конструктор:**
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

**Поля класса:**
- `baseUrl: string` - базовый адрес сервера
- `options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

**Методы класса:**
- `get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер
- `post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.
- `handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

**Поля класса:**
- `_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

**Методы класса:**
- `on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.
- `emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.
- `trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Типы данных

В приложении используются следующие типы и интерфейсы данных.

### TPayment

Тип, определяющий доступные способы оплаты.

```typescript
type TPayment = 'card' | 'cash';
```

**Назначение:** Используется для указания способа оплаты при оформлении заказа. Может принимать значения 'card' (банковская карта) или 'cash' (наличные).

---

### IProduct

Интерфейс описывает товар в каталоге интернет-магазина.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор товара |
| `description` | `string` | Описание товара |
| `image` | `string` | URL изображения товара |
| `title` | `string` | Название товара |
| `category` | `string` | Категория товара |
| `price` | `number \| null` | Цена товара (может быть null, если товар недоступен) |

```typescript
interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}
```

**Назначение:** Описывает структуру товара, получаемого с сервера и используемого в приложении. Используется в моделях Products и Cart для хранения и управления товарами.

---

### IBuyer

Интерфейс описывает данные покупателя, необходимые для оформления заказа.

| Поле | Тип | Описание |
|------|-----|----------|
| `payment` | `TPayment \| null` | Способ оплаты ('card' или 'cash') или null, если не выбран |
| `email` | `string` | Email покупателя |
| `phone` | `string` | Телефон покупателя |
| `address` | `string` | Адрес доставки |

```typescript
interface IBuyer {
    payment: TPayment | null;
    email: string;
    phone: string;
    address: string;
}
```

**Назначение:** Описывает структуру данных покупателя. Используется в модели Buyer для хранения и валидации данных при оформлении заказа. Поле `payment` инициализируется значением `null` и сбрасывается в `null` при очистке.

---

### TBuyerErrors

Тип ошибок валидации данных покупателя.

```typescript
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

**Назначение:** Используется для типизации объекта, возвращаемого методом `validate()` модели Buyer. Ключами объекта являются поля интерфейса `IBuyer`, значениями - тексты ошибок. Все поля необязательны.

---

### IProductsResponse

Тип ответа сервера при получении списка товаров.

| Поле | Тип | Описание |
|------|-----|----------|
| `items` | `IProduct[]` | Массив товаров |
| `total` | `number` | Общее количество товаров |

```typescript
interface IProductsResponse {
    items: IProduct[];
    total: number;
}
```

**Назначение:** Описывает структуру ответа сервера на GET-запрос к эндпоинту `/product`. Используется в классе AppApi для типизации получаемых данных.

---

### IOrderData

Тип данных, отправляемых на сервер при оформлении заказа. Расширяет интерфейс `IBuyer`.

| Поле | Тип | Описание |
|------|-----|----------|
| `payment` | `TPayment` | Способ оплаты (переопределен - не может быть null) |
| `email` | `string` | Email покупателя (наследуется от IBuyer) |
| `phone` | `string` | Телефон покупателя (наследуется от IBuyer) |
| `address` | `string` | Адрес доставки (наследуется от IBuyer) |
| `items` | `string[]` | Массив id товаров в заказе |
| `total` | `number` | Общая стоимость заказа |

```typescript
interface IOrderData extends IBuyer {
    payment: TPayment;
    items: string[];
    total: number;
}
```

**Назначение:** Описывает структуру данных, отправляемых на сервер при оформлении заказа. Используется в классе AppApi для типизации POST-запроса к эндпоинту `/order`. Расширяет `IBuyer` для устранения дублирования полей.

```typescript
interface IOrderResponse {

    total: number;
}

**Назначение:** Описывает структуру ответа сервера на POST-запрос к эндпоинту `/order`. Используется в классе AppApi для типизации получаемых данных после оформления заказа.

Интерфейс для работы с API.

interface IApi {

**Назначение:** Описывает контракт для класса, осуществляющего HTTP-запросы. Используется в классе AppApi для реализации композиции.

## Модели данных

Модели отвечают за хранение данных, полученных с сервера, и работу с ними.

### Класс Products

Хранение и работа с полным списком товаров, доступных в магазине, выбор товара для предварительного просмотра.

**Зона ответственности:**
- Хранение списка всех товаров
- Хранение выбранного для просмотра товара
- Предоставление доступа к данным о товарах

**Конструктор:**
`constructor(events: IEvents)` - принимает брокер событий для генерации событий при изменении данных.

**Поля класса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `items` | `IProduct[]` | Массив всех товаров в каталоге |
| `selectedProduct` | `IProduct \| null` | Товар, выбранный для детального просмотра |

**Методы класса:**

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `setItems` | `items: IProduct[]` | `void` | Сохраняет массив товаров в каталог. Генерирует событие `items:changed` |
| `getItems` | - | `IProduct[]` | Возвращает массив всех товаров |
| `getProductById` | `id: string` | `IProduct \| undefined` | Возвращает товар по его id |
| `setSelectedProduct` | `product: IProduct` | `void` | Сохраняет товар для детального просмотра. Генерирует событие `preview:changed` |
| `getSelectedProduct` | - | `IProduct \| null` | Возвращает выбранный для просмотра товар |

```typescript
class Products {
    private items: IProduct[];
    private selectedProduct: IProduct | null;
    
    constructor(protected events: IEvents);
    setItems(items: IProduct[]): void;
    getItems(): IProduct[];
    getProductById(id: string): IProduct | undefined;
    setSelectedProduct(product: IProduct): void;
    getSelectedProduct(): IProduct | null;
}
```

### Класс Cart

Управляет списком товаров, которые пользователь планирует купить.

**Зона ответственности:**
- Хранение товаров, добавленных в корзину
- Управление составом корзины
- Расчет общей стоимости и количества товаров

**Конструктор:**
`constructor(events: IEvents)` - принимает брокер событий для генерации событий при изменении данных.

**Поля класса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `items` | `IProduct[]` | Массив товаров в корзине |

**Методы класса:**

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `getItems` | - | `IProduct[]` | Возвращает массив товаров в корзине |
| `addItem` | `product: IProduct` | `void` | Добавляет товар в корзину (если его там нет). Генерирует событие `basket:changed` |

| `isProductInCart` | `productId: string` | `boolean` | Проверяет, находится ли товар в корзине |

class Cart {
    private items: IProduct[];
    
    constructor(protected events: IEvents);

    clear(): void;
    getTotalPrice(): number;
    getItemCount(): number;

### Класс Buyer

Хранит данные покупателя и отвечает за их валидацию перед отправкой заказа.

**Зона ответственности:**
- Хранение данных покупателя
- Частичное обновление данных
- Валидация данных согласно функциональным требованиям

**Конструктор:**
`constructor(events: IEvents)` - принимает брокер событий для генерации событий при изменении данных.

**Поля класса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `data` | `IBuyer` | Объект с данными покупателя |

**Методы класса:**

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `setData` | `data: Partial<IBuyer>` | `void` | Сохраняет данные покупателя (частично или полностью). Генерирует событие `buyer:changed` |
| `getData` | - | `IBuyer` | Возвращает все данные покупателя |
| `clear` | - | `void` | Очищает все данные покупателя. Генерирует событие `buyer:changed` |
| `validate` | - | `TBuyerErrors` | Валидирует все поля, возвращает объект с ошибками |

**Особенности реализации:**
- Метод `setData` позволяет обновлять как все поля, так и отдельные поля, не теряя остальные данные
- Поле `payment` инициализируется значением `null` и сбрасывается в `null` при очистке
- Метод `validate` возвращает объект типа `TBuyerErrors`, где ключи - это названия полей, а значения - текст ошибки
- Поле считается валидным, если оно не пустое (не `undefined`, не `null`, не пустая строка)

```typescript
class Buyer {
    private data: IBuyer;
    
    constructor(protected events: IEvents);
    setData(data: Partial<IBuyer>): void;
    getData(): IBuyer;
    clear(): void;
    validate(): TBuyerErrors;
}
```

## Слой коммуникации

Отвечает за получение данных с сервера и отправку данных на сервер.

### Класс AppApi

Непосредственное взаимодействие с бэкендом магазина. Преобразует ответы от сервера в типизированные данные, с которыми удобно работать моделям.

**Зона ответственности:**
- Выполнение HTTP-запросов к серверу
- Получение данных о товарах
- Отправка данных о заказе

**Конструктор:**
`constructor(api: IApi)` - принимает экземпляр класса, реализующего интерфейс `IApi` (используется **композиция**).

**Поля класса:**

| Поле | Тип | Описание |
|------|-----|----------|
| `api` | `IApi` | Экземпляр класса для выполнения HTTP-запросов |

**Методы класса:**

| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `getProducts` | - | `Promise<IProductsResponse>` | GET-запрос к эндпоинту `/product` |
| `postOrder` | `orderData: IOrderData` | `Promise<IOrderResponse>` | POST-запрос к эндпоинту `/order` |

**Особенности реализации:**
- Класс использует **композицию** - принимает в конструктор экземпляр класса, реализующего интерфейс `IApi`
- Зависимость от интерфейса `IApi`, а не от конкретной реализации
- Не использует наследование от `Api`
- Не содержит собственного конструктора с `baseUrl`
- Тип ответа задаётся дженериком: `this.api.get<IProductsResponse>('/product')`

```typescript
class AppApi {
    constructor(protected api: IApi);
    getProducts(): Promise<IProductsResponse>;
    postOrder(orderData: IOrderData): Promise<IOrderResponse>;
}
```

## Архитектурный слой: Презентер (Связующий слой)

Презентер реализован в главном скрипте приложения `src/main.ts`. Его основная задача — управление взаимодействием между Моделями данных и Компонентами представления с помощью событийно-ориентированного подхода.

### Принципы работы Презентера:

1. **Реактивность:** Презентер никогда не вызывает принудительный перерендер интерфейса сразу после вызова методов изменения данных в модели. Перерисовка View происходит строго в ответ на события, генерируемые Моделями после того, как данные внутри них были успешно изменены.

2. **Изоляция:** Компоненты View и Model ничего не знают друг о друге. Их общение инкапсулировано внутри обработчиков событий Презентера.

3. **Отсутствие генерации:** Презентер только слушает (`events.on`) и обрабатывает события. Сам Презентер новые события в брокер не отправляет.

### Основные обработчики Презентера:

| Событие | Действие |
|---------|----------|
| `items:changed` | Создание карточек и отрисовка галереи |
| `preview:changed` | Открытие модального окна с карточкой товара |
| `basket:changed` | Обновление счетчика и содержимого корзины |
| `basket:open` | Открытие модального окна с корзиной |
| `order:open` | Очистка данных и открытие формы заказа |
| `order.payment:change` | Сохранение способа оплаты и валидация |
| `order.address:change` | Сохранение адреса и валидация |
| `order:submit` | Переход к форме контактов |
| `contacts.email:change` | Сохранение email и валидация |
| `contacts.phone:change` | Сохранение телефона и валидация |
| `contacts:submit` | Отправка заказа на сервер |
| `modal:open` | Блокировка прокрутки страницы |
| `modal:close` | Разблокировка прокрутки страницы |
```
